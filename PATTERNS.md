## State Machine Pattern

**Location**: `crates/loom-common-core/src/agent.rs`, `crates/loom-common-core/src/state.rs`

The Agent uses an explicit state machine with three components:
- **`AgentState`**: Current state (WaitingForUserInput, CallingLlm, ExecutingTools, etc.)
- **`AgentEvent`**: Input events (UserInput, LlmEvent, ToolCompleted, etc.)
- **`AgentAction`**: Output actions the caller must execute

```rust
// The state machine is PASSIVE - it doesn't drive itself
fn handle_event(&mut self, event: AgentEvent) -> AgentAction {
    match (&self.state, event) {
        (AgentState::WaitingForUserInput, AgentEvent::UserInput(msg)) => {
            self.state = AgentState::CallingLlm { ... };
            AgentAction::SendLlmRequest(request)
        }
        // ... more transitions
    }
}
```

**Why**: Separates state logic from async I/O. The state machine is synchronous and testable; the caller handles async operations.

**Related Discoveries**: [001](discoveries/001-primary-purpose.md), [008](discoveries/008-retry-timeout-mechanism.md), [016](discoveries/016-shared-agent-runtime-analysis.md)

## Registry Pattern

**Location**: `crates/loom-cli-tools/src/registry.rs`

Tools are registered in a central registry using trait objects:

```rust
pub struct ToolRegistry {
    tools: HashMap<String, Box<dyn Tool>>,
}

impl ToolRegistry {
    pub fn register(&mut self, tool: Box<dyn Tool>) {
        self.tools.insert(tool.name().to_string(), tool);
    }
    
    pub fn get(&self, name: &str) -> Option<&dyn Tool> {
        self.tools.get(name).map(|t| t.as_ref())
    }
}
```

**Why**: Enables dynamic tool discovery and invocation by name (as returned by LLM).

**Related Discoveries**: [020](discoveries/020-tool-trait-is-mutating-method.md)

## Proxy Pattern

**Location**: `crates/loom-server-llm-proxy/`, `crates/loom-server/src/llm_proxy.rs`

All LLM communication goes through a server-side proxy:

```
CLI (ProxyLlmClient) → HTTP → Server (LlmService) → Provider API
```

```rust
// Client side
impl LlmClient for ProxyLlmClient {
    async fn complete_streaming(&self, request: LlmRequest) -> Result<LlmStream, LlmError> {
        let response = self.http_client
            .post(&self.stream_url())
            .json(&request)
            .send().await?;
        // Parse SSE stream...
    }
}
```

**Why**: API keys never leave the server. Centralized credential management and rate limiting.

**Related Discoveries**: [003](discoveries/003-request-flow.md), [013](discoveries/013-proxy-llm-client-503-handling.md)

## SSE Streaming Pattern

**Location**: `crates/loom-server/src/llm_proxy.rs`, `crates/loom-server-llm-proxy/src/stream.rs`

LLM responses stream via Server-Sent Events with a "double-wrap" strategy:

```rust
// Server wraps provider events
let stream_event = LlmStreamEvent::TextDelta { content };
Event::default().event("llm").data(serde_json::to_string(&stream_event)?)

// Client parses SSE back to LlmEvent
fn parse_sse_line(line: &str) -> Option<LlmEvent> {
    if line.starts_with("data: ") {
        let json = &line[6..];
        serde_json::from_str::<LlmStreamEvent>(json).ok()?.into()
    }
}
```

**Why**: Allows server to inject custom events (like `ServerQuery` for human-in-the-loop) without breaking provider protocol.

**Related Discoveries**: [007](discoveries/007-sse-error-handling.md)

## Trait-Based Extensibility

**Location**: Throughout codebase

Core abstractions are defined as traits with default implementations:

```rust
#[async_trait]
pub trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn input_schema(&self) -> serde_json::Value;
    
    // Default implementation
    fn to_definition(&self) -> ToolDefinition {
        ToolDefinition {
            name: self.name().to_string(),
            description: self.description().to_string(),
            input_schema: self.input_schema(),
        }
    }
    
    async fn invoke(&self, args: Value, ctx: &ToolContext) -> Result<Value, ToolError>;
}
```

**Why**: New tools/providers can be added by implementing traits without modifying core code.

**Related Discoveries**: [020](discoveries/020-tool-trait-is-mutating-method.md)

## Builder Pattern

**Location**: `crates/loom-common-core/src/request.rs`

Request objects use builders for ergonomic construction:

```rust
let request = LlmRequest::new("claude-3-5-sonnet")
    .with_messages(messages)
    .with_tools(tool_definitions)
    .with_system_prompt(system)
    .with_max_tokens(4096);
```

**Why**: Avoids large constructors with many optional parameters.

## Error Response Pattern

**Location**: `crates/loom-server/src/error.rs`, `crates/loom-server/src/api_response.rs`

HTTP errors use a consistent JSON structure:

```rust
pub struct ErrorResponse {
    pub error: String,      // Machine-readable code: "not_found", "conflict"
    pub message: String,    // Human-readable explanation
}

// Helper functions for common cases
pub fn not_found<T: ApiErrorResponse>(message: impl Into<String>) -> (StatusCode, Json<T>) {
    (StatusCode::NOT_FOUND, Json(T::new("not_found", message)))
}
```

**Why**: Consistent error format across all endpoints. Machine-readable codes enable programmatic handling.

**Related Discoveries**: [021](discoveries/021-cli-json-error-parsing.md), [038](discoveries/038-error-code-in-displayed-message.md)

## Secret Wrapper Pattern

**Location**: `crates/loom-common-secret/`

Sensitive values are wrapped to prevent accidental exposure:

```rust
pub struct Secret<T>(T);

impl<T> Secret<T> {
    pub fn expose(&self) -> &T { &self.0 }
}

impl<T> Debug for Secret<T> {
    fn fmt(&self, f: &mut Formatter<'_>) -> fmt::Result {
        write!(f, "[REDACTED]")
    }
}
```

**Why**: Secrets are automatically redacted in logs, debug output, and serialization.

## Hook Pattern

**Location**: `crates/loom-cli-auto-commit/`

Post-processing is implemented via hooks:

```rust
#[async_trait]
pub trait PostToolHook: Send + Sync {
    async fn run(&self, context: &HookContext) -> Result<HookResult>;
}

// Auto-commit hook
impl PostToolHook for AutoCommitHook {
    async fn run(&self, ctx: &HookContext) -> Result<HookResult> {
        if ctx.has_mutating_tools() {
            self.service.maybe_commit().await?;
        }
        Ok(HookResult::Continue)
    }
}
```

**Why**: Decouples post-tool behavior from core agent logic. Hooks can be composed.

**Related Discoveries**: [005](discoveries/005-post-tools-hook-auto-commit.md)

## Retry with Backoff Pattern

**Location**: `crates/loom-common-http/src/retry.rs`

HTTP requests use exponential backoff with jitter:

```rust
fn calculate_delay(cfg: &RetryConfig, attempt: u32) -> Duration {
    let base = cfg.base_delay.as_secs_f64();
    let exponential = base * cfg.backoff_factor.powi(attempt as i32);
    let jitter = rand::thread_rng().gen_range(-0.15..0.15);
    Duration::from_secs_f64(exponential * (1.0 + jitter))
}
```

**Why**: Prevents thundering herd on transient failures. Jitter spreads retry attempts.

**Related Discoveries**: [033](discoveries/033-jitter-for-retry-after-values.md)

## Typed Router Pattern

**Location**: `crates/loom-server/src/typed_router.rs`

Routes are organized by authentication requirement:

```rust
pub struct PublicRouter(Router);   // No auth required
pub struct AuthedRouter(Router);   // Bearer token required

// Usage
let public = PublicRouter::new()
    .route("/health", get(health_handler));

let authed = AuthedRouter::new()
    .route("/api/threads", get(list_threads));
```

**Why**: Compile-time separation of public vs protected routes. Prevents accidentally exposing authenticated endpoints.

## Migration Pattern

**Location**: `crates/loom-server/migrations/`

Database migrations are numbered SQL files:

```
migrations/
├── 001_initial.sql
├── 002_users.sql
├── 020_scm_repos.sql
└── ...
```

**Rules**:
- All migrations go in `loom-server/migrations/` (not scattered across crates)
- Run automatically on server startup
- After adding migrations, run `cargo2nix-update` (migrations use `include_str!`)

## Instrumentation Pattern

**Location**: Throughout codebase

Functions use `#[instrument]` with explicit skip/fields:

```rust
#[instrument(skip(self, request), fields(model = %request.model, provider = %self.provider))]
async fn complete(&self, request: LlmRequest) -> Result<LlmResponse, LlmError> {
    // ...
}
```

**Rules**:
- Always skip `self`, secrets, and large arguments
- Add meaningful fields for debugging
- Use `%` for Display, `?` for Debug

## Summary

| Pattern | Purpose | Key Benefit |
|---------|---------|-------------|
| State Machine | Agent behavior | Testable, explicit transitions |
| Registry | Tool management | Dynamic discovery by name |
| Proxy | LLM communication | Server-side credentials |
| SSE Streaming | Real-time responses | Low latency, custom events |
| Trait Extensibility | Adding providers/tools | No core modifications |
| Builder | Request construction | Ergonomic optional params |
| Error Response | HTTP errors | Consistent, machine-readable |
| Secret Wrapper | Credential protection | Auto-redaction |
| Hook | Post-processing | Composable behavior |
| Retry with Backoff | Transient failures | Thundering herd prevention |
| Typed Router | Route organization | Auth requirement clarity |

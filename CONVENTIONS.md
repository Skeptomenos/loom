# Conventions: Loom

> Generated by ralphus-discover
> Last updated: 2026-01-16

This document captures the implicit and explicit conventions used throughout the Loom codebase.

## Code Style

### Formatting (rustfmt.toml)

```toml
hard_tabs = true
tab_spaces = 2
max_width = 100
```

- **Hard tabs** with 2-space display width
- **100 character** line width
- Run `cargo fmt --all` before committing

### Linting

```bash
cargo clippy --workspace -- -D warnings
```

All clippy warnings are treated as errors. Fix them, don't suppress them.

## Naming Conventions

### Crates

Pattern: `loom-{domain}-{component}`

| Domain | Examples |
|--------|----------|
| `server` | `loom-server`, `loom-server-llm-anthropic`, `loom-server-auth-github` |
| `cli` | `loom-cli`, `loom-cli-tools`, `loom-cli-acp` |
| `common` | `loom-common-core`, `loom-common-http`, `loom-common-secret` |
| `tui` | `loom-tui-app`, `loom-tui-widgets` |

### Files

- **Rust files**: `snake_case.rs` (e.g., `edit_file.rs`, `llm_proxy.rs`)
- **Migrations**: `NNN_description.sql` (e.g., `020_scm_repos.sql`)
- **Specs**: `kebab-case.md` (e.g., `state-machine.md`)

### Rust Elements

| Element | Convention | Example |
|---------|------------|---------|
| Functions | `snake_case` | `execute_tool`, `has_mutating_tools` |
| Methods | `snake_case` | `with_messages`, `to_definition` |
| Types/Structs | `PascalCase` | `AgentState`, `ToolRegistry` |
| Traits | `PascalCase` | `Tool`, `LlmClient`, `PostToolHook` |
| Enums | `PascalCase` | `LlmEvent`, `AgentAction` |
| Enum Variants | `PascalCase` | `TextDelta`, `ExecutingTools` |
| Constants | `SCREAMING_CASE` | `MUTATING_TOOLS`, `DEFAULT_MODEL` |
| Type Aliases | `PascalCase` | `Result<T>` (per-crate) |

### Error Codes (API)

Machine-readable error codes use `snake_case`:

```rust
error: "not_found"
error: "already_member"
error: "invalid_email"
error: "rate_limited"
```

## Error Handling

### Crate-Level Error Types

Each crate defines its own error enum with `thiserror`:

```rust
// crates/loom-foo/src/error.rs
#[derive(Debug, thiserror::Error)]
pub enum FooError {
    #[error("Database error: {0}")]
    Db(#[from] sqlx::Error),
    
    #[error("Not found: {0}")]
    NotFound(String),
}
```

### Result Type Aliases

Each crate defines a `Result<T>` alias:

```rust
pub type Result<T> = std::result::Result<T, FooError>;
```

### Error Propagation

Use `anyhow` for adding context:

```rust
let data = fs::read_to_string(&path)
    .context("failed to read config file")?;
```

### Never Suppress Errors

```rust
// BAD
let _ = do_something();

// GOOD
if let Err(e) = do_something() {
    tracing::warn!(error = %e, "operation failed, continuing");
}
```

## Async Conventions

### Runtime

All async code uses **Tokio**:

```rust
#[tokio::main]
async fn main() -> Result<()> {
    // ...
}
```

### Async Traits

Use `async-trait` for async trait methods:

```rust
use async_trait::async_trait;

#[async_trait]
pub trait Tool: Send + Sync {
    async fn invoke(&self, args: Value, ctx: &ToolContext) -> Result<Value, ToolError>;
}
```

### Send + Sync Bounds

Traits that will be used across threads require `Send + Sync`:

```rust
pub trait Tool: Send + Sync { ... }
```

## Logging & Instrumentation

### Structured Logging

Use `tracing` with structured fields:

```rust
use tracing::{debug, info, warn, error, instrument};

info!(user_id = %user.id, action = "login", "user logged in");
warn!(error = %e, "operation failed");
```

### Function Instrumentation

```rust
#[instrument(skip(self, request), fields(model = %request.model))]
async fn complete(&self, request: LlmRequest) -> Result<LlmResponse> {
    // ...
}
```

**Rules**:
- Always `skip(self)` (not useful in logs)
- Always skip secrets and large arguments
- Add meaningful fields with `%` (Display) or `?` (Debug)

### Never Log Secrets

```rust
// BAD
debug!(api_key = %key, "using key");

// GOOD - Secret<T> auto-redacts
debug!(api_key = ?secret_key, "using key");  // Logs "[REDACTED]"
```

## HTTP Conventions

### Client Construction

Never build `reqwest::Client` directly:

```rust
// BAD
let client = reqwest::Client::new();

// GOOD
let client = loom_common_http::new_client();
```

This ensures consistent User-Agent and retry configuration.

### Error Responses

All HTTP errors return JSON with `error` and `message` fields:

```rust
pub struct ErrorResponse {
    pub error: String,      // Machine-readable: "not_found"
    pub message: String,    // Human-readable: "Thread not found: abc123"
}
```

### Route Organization

Use typed routers to separate auth requirements:

```rust
// Public routes (no auth)
let public = PublicRouter::new()
    .route("/health", get(health));

// Protected routes (bearer token required)
let authed = AuthedRouter::new()
    .route("/api/threads", get(list_threads));
```

## Database Conventions

### Migrations

- **Location**: `crates/loom-server/migrations/` only
- **Naming**: `NNN_description.sql` (check existing for next number)
- **After adding**: Run `cargo2nix-update` (migrations use `include_str!`)

### Queries

Use sqlx with compile-time checking:

```rust
let thread = sqlx::query_as!(
    ThreadRow,
    "SELECT id, title, created_at FROM threads WHERE id = ?",
    thread_id
)
.fetch_optional(&pool)
.await?;
```

## Testing Conventions

### Unit Tests

Place in `#[cfg(test)]` module within the source file:

```rust
#[cfg(test)]
mod tests {
    use super::*;
    
    #[test]
    fn test_something() {
        // ...
    }
    
    #[tokio::test]
    async fn test_async_something() {
        // ...
    }
}
```

### Integration Tests

Place in `tests/` directory:

```
crates/loom-server/
├── src/
└── tests/
    ├── authz_thread_tests.rs
    └── authz_org_tests.rs
```

### Authorization Tests

When adding/modifying routes, update `tests/authz_*_tests.rs`:

```rust
#[tokio::test]
async fn test_list_threads_requires_auth() {
    let response = client.get("/api/threads").send().await;
    assert_eq!(response.status(), StatusCode::UNAUTHORIZED);
}
```

## Git Conventions

### Remotes

- **origin**: `ghuntley/loom` (upstream, read-only for agents)
- **fork**: `Skeptomenos/loom` (writable for agent contributions)

### Pushing Changes

```bash
git push fork <branch-name>
```

### Commit Messages

Descriptive but no strict format. Examples:

```
Add is_mutating() method to Tool trait
Fix SSE stream parsing for partial events
Update cargo2nix after adding migration
```

### Branch Strategy

Trunk-based development on `trunk` branch. Deploy by pushing to trunk.

## Svelte 5 Conventions (Web Frontend)

**Always use Svelte 5 runes. Never use Svelte 4 patterns.**

| Category | ✅ Svelte 5 | ❌ Svelte 4 (DO NOT USE) |
|----------|-------------|--------------------------|
| State | `let count = $state(0);` | `let count = 0;` |
| Derived | `const doubled = $derived(count * 2);` | `$: doubled = count * 2;` |
| Effects | `$effect(() => { ... });` | `$: { ... }` |
| Props | `let { foo, bar } = $props();` | `export let foo;` |
| Events | `onclick={handler}` | `on:click={handler}` |
| Custom events | Pass callback props: `onsave={fn}` | `createEventDispatcher` |
| Slots | `{@render children()}` | `<slot />` |

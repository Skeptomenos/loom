# Gotchas: Loom

> Generated by ralphus-discover
> Last updated: 2026-01-16

This document captures non-obvious behaviors, quirks, and "gotchas" that new developers should know.

---

## Critical Gotchas

### 1. API Keys Never Leave the Server

**What**: The CLI (`loom-cli`) never has direct access to LLM provider API keys. All LLM requests go through `ProxyLlmClient` → Server → Provider.

**Why It Matters**: If you're debugging LLM issues, check both client-side (`ProxyLlmClient`) and server-side (`llm_proxy.rs`) logs. The CLI only sees HTTP errors, not provider-specific errors.

**Discovery**: [001-primary-purpose](discoveries/001-primary-purpose.md)

---

### 2. Sequential Tool Execution is Intentional

**What**: The Agent state machine supports parallel tool execution, but the CLI runs tools sequentially.

**Why**: No file locking mechanism exists. Parallel execution of `edit_file` or `bash` could cause race conditions and data corruption.

**Implication**: Don't enable parallel execution without first implementing file locks (see [012-workspace-lock-manager-analysis](discoveries/012-workspace-lock-manager-analysis.md)).

**Discovery**: [004-sequential-execution-rationale](discoveries/004-sequential-execution-rationale.md)

---

### 3. Agent State Machine is Passive

**What**: The `Agent` struct receives events and returns actions. It does NOT drive itself.

**Why It Matters**: The caller (CLI, ACP, or future runtime) must implement the event loop:
```rust
loop {
    let action = agent.handle_event(event);
    match action {
        AgentAction::SendLlmRequest(req) => { /* caller sends request */ }
        AgentAction::ExecuteTool(call) => { /* caller executes tool */ }
        // ...
    }
}
```

**Implication**: If you're building a new consumer, you must implement the full event loop. There's no shared `AgentRuntime` abstraction yet.

**Discovery**: [016-shared-agent-runtime-analysis](discoveries/016-shared-agent-runtime-analysis.md)

---

### 4. Retry Mechanism is Dead Code

**What**: The Agent has a `RetryTimeoutFired` event and retry state, but NO consumer ever fires this event.

**Why It Matters**: If you expect automatic retries on LLM failures, they won't happen. The retry logic exists but is never triggered.

**Implication**: Either implement timer firing in CLI/ACP, or rely on HTTP-level retries in `loom-common-http`.

**Discovery**: [008-retry-timeout-mechanism](discoveries/008-retry-timeout-mechanism.md), [015-cli-acp-retry-timer-intentionality](discoveries/015-cli-acp-retry-timer-intentionality.md)

---

### 5. cargo2nix-update Required After Certain Changes

**What**: After modifying `Cargo.toml`, `Cargo.lock`, or adding migrations, you MUST run `cargo2nix-update`.

**Why**: 
- `Cargo.nix` is the source of truth for Nix builds
- Migrations use `include_str!` which cargo2nix doesn't track automatically

**Symptom**: Deployed binary doesn't include your new migration or dependency.

**Fix**: Always run `cargo2nix-update` and commit `Cargo.nix` with your changes.

---

### 6. Svelte 5 Only - Never Use Svelte 4 Patterns

**What**: The web frontend uses Svelte 5 runes exclusively.

**Forbidden Patterns**:
- `export let foo;` → Use `let { foo } = $props();`
- `$: derived = x * 2;` → Use `const derived = $derived(x * 2);`
- `on:click={handler}` → Use `onclick={handler}`
- `<slot />` → Use `{@render children()}`

**Why It Matters**: Mixing Svelte 4 and 5 patterns causes subtle bugs and inconsistent behavior.

## Implementation Gotchas

### 7. MUTATING_TOOLS is a Hardcoded List

**What**: The list of tools that trigger auto-commit is hardcoded in `agent.rs`:
```rust
const MUTATING_TOOLS: &[&str] = &["edit_file", "write_file", "bash", ...];
```

**Why It Matters**: Adding a new mutating tool requires updating this list manually.

**Better Solution**: Add `is_mutating()` method to the `Tool` trait (see [020-tool-trait-is-mutating-method](discoveries/020-tool-trait-is-mutating-method.md)).

---

### 8. ProxyLlmClient Doesn't Parse Retry-After Header

**What**: When the server returns 429/503 with `Retry-After`, the client ignores it.

**Code**:
```rust
LlmError::RateLimited {
    retry_after_secs: None,  // Always None
    message: body,
}
```

**Implication**: Clients can't implement intelligent backoff based on server hints.

**Discovery**: [009-proxy-llm-client-retry-after](discoveries/009-proxy-llm-client-retry-after.md)

---

### 9. SSE Partial Events Are Discarded on Disconnect

**What**: If an SSE connection drops mid-event, the partial data is lost.

**Why It Matters**: Long LLM responses may be truncated without error indication.

**No Automatic Reconnection**: The client doesn't reconnect and resume. The Agent's retry mechanism (if implemented) would restart the entire request.

**Discovery**: [007-sse-error-handling](discoveries/007-sse-error-handling.md)

---

### 10. Error Codes Are Inconsistently Useful

**What**: API error codes fall into two categories:
- **Generic** (redundant with HTTP status): `not_found`, `bad_request`, `forbidden`
- **Domain-specific** (actionable): `already_member`, `last_owner`, `slug_exists`

**Implication**: When displaying errors to users, include domain-specific codes but omit generic ones.

**Discovery**: [038-error-code-in-displayed-message](discoveries/038-error-code-in-displayed-message.md)

---

## Performance Gotchas

### 11. No Parallel Tool Execution Yet

**What**: Even read-only tools (like `read_file`, `glob`) run sequentially.

**Opportunity**: Read-only tools could safely run in parallel, improving performance for exploration-heavy tasks.

**Blocker**: Requires implementing parallel execution infrastructure and tool classification.

**Discovery**: [011-read-only-tools-parallelization](discoveries/011-read-only-tools-parallelization.md)

---

### 12. FTS5 Search Requires Specific Query Syntax

**What**: Thread search uses SQLite FTS5, which has specific query syntax.

**Gotcha**: Queries with special characters may fail or return unexpected results.

**Tip**: Escape special characters or use phrase queries with quotes.

---

## Debugging Gotchas

### 13. Two Places to Check for LLM Errors

**What**: LLM errors can occur at:
1. **Client side** (`ProxyLlmClient`): HTTP errors, connection issues
2. **Server side** (`llm_proxy.rs`): Provider errors, rate limits, auth failures

**Tip**: Always check both log sources when debugging LLM issues.

---

### 14. Weaver Pods May Exit Immediately

**What**: If a Weaver pod shows "Succeeded" status immediately, the container exited.

**Cause**: The container image has no long-running entrypoint.

**Fix**: Weaver images must run a persistent process (the loom REPL).

**Debug**: `kubectl describe pod <name> -n loom-weavers`

---

### 15. ErrImagePull Means Image Doesn't Exist

**What**: Kubernetes can't pull the Weaver container image.

**Causes**:
- Image doesn't exist in registry
- Image is private and no pull secret configured
- Typo in image name

**Debug**: Check `kubectl describe pod` for the exact error.

---

## Security Gotchas

### 16. Secret<T> Only Protects Against Accidental Logging

**What**: `Secret<T>` auto-redacts in Debug/Display/Serialize, but `.expose()` returns the raw value.

**Not Protected Against**:
- Intentional exposure via `.expose()`
- Memory dumps
- Core dumps

**Rule**: Never log the result of `.expose()`.

---

### 17. Dev Mode Bypasses All Auth

**What**: `LOOM_SERVER_AUTH_DEV_MODE=1` disables authentication entirely.

**Danger**: Never enable in production. All routes become public.

**Use Case**: Local development and testing only.

---

## Build System Gotchas

### 18. Nix Builds Don't Track include_str! Changes

**What**: If you add a migration file, Nix won't detect the change because `include_str!` is evaluated at Rust compile time, not Nix evaluation time.

**Fix**: Run `cargo2nix-update` to regenerate `Cargo.nix` with new hashes.

---

### 19. Two Remotes: origin vs fork

**What**: 
- `origin` = `ghuntley/loom` (upstream, read-only for agents)
- `fork` = `Skeptomenos/loom` (writable for contributions)

**Gotcha**: Pushing to `origin` will fail for agents.

**Fix**: Always use `git push fork <branch>`.

## Quick Reference: Common Mistakes

| Mistake | Symptom | Fix |
|---------|---------|-----|
| Forgot `cargo2nix-update` | Migration not in deployed binary | Run `cargo2nix-update`, commit `Cargo.nix` |
| Used Svelte 4 syntax | Reactivity doesn't work | Use `$state`, `$derived`, `$effect` |
| Pushed to `origin` | Permission denied | Use `git push fork <branch>` |
| Expected parallel tools | Tools run slowly | Sequential is intentional (no file locks) |
| Expected auto-retry | LLM errors not retried | Retry timer never fired (dead code) |
| Added mutating tool | Auto-commit doesn't trigger | Add to `MUTATING_TOOLS` list |
| Used `reqwest::Client::new()` | Missing User-Agent, no retries | Use `loom_common_http::new_client()` |
| Logged secret directly | Secret exposed in logs | Use `Secret<T>` wrapper |
